Introduction — the task

This activity asked for a dialogue between two agents built on KQML (Knowledge Query and Manipulation Language) and KIF (Knowledge Interchange Format). Alice is a procurement agent that buys stock; Bob controls stock levels for a warehouse. Alice must discover two facts before purchasing: how many 50-inch televisions are available, and how many HDMI slots each set has.

The two languages divide the work cleanly. KQML is the outer envelope: its performatives express the sender's intent as a speech act. KIF is the content inside the envelope: logical expressions stating queries and facts. A shared ontology, warehouse-stock, guarantees that both agents mean the same thing by every term. Because of this separation, Alice never needs to know how Bob stores his data, and Bob never needs to know why Alice is asking — the loose coupling that motivates agent-based computing in heterogeneous systems.

Why agents at all? In supply chains, systems from different vendors and eras must cooperate without sharing internals. Knowledge-level messaging is the alternative to brittle point-to-point integration.

The ontology

Before any message is exchanged, both agents commit to the warehouse-stock ontology. It defines the classes, the instance being discussed, and the functions that map a product to a value:

;; Ontology: warehouse-stock
;; Classes
(defclass Product)
(defclass Television :subclass-of Product)

;; Instances
(instance-of television-50inch Television)

;; Functions (each Product maps to a value)
(deffunction available-stock (?p Product) :-> Integer)   ; units on hand
(deffunction hdmi-slots      (?p Product) :-> Integer)   ; HDMI ports per unit
(deffunction screen-size     (?p Product) :-> Integer)   ; inches

The ontology is what turns syntax into meaning. Without it, a message could be perfectly well-formed KQML and still be uninterpretable — or worse, interpreted differently by each side, producing confidently wrong answers rather than errors.

The hard problem. Ontology alignment remains one of the major unsolved challenges in multi-agent systems. If Bob counted pallets while Alice expected units, both agents would proceed happily — and incorrectly.

The dialogue at a glance

Reading the diagram. Time flows downward. Navy arrows are Alice's queries; mauve and slate arrows are Bob's capability advert and answers.

The dialogue, message by message

0 · advertise — Bob → Alice
(advertise
  :sender    Bob
  :receiver  Alice
  :language  KQML
  :ontology  warehouse-stock
  :content   (ask-one :content (available-stock ?product ?quantity)))
What this box does. Bob commits publicly to a capability: he can answer ask-one queries about stock. Capability discovery is what lets agents find each other dynamically instead of being hard-wired together. Note the content is itself a KQML expression — the advert describes the shape of messages Bob accepts.
1 · ask-one — Alice → Bob
(ask-one
  :sender      Alice
  :receiver    Bob
  :language    KIF
  :ontology    warehouse-stock
  :reply-with  query-tv-stock-01
  :content     (available-stock television-50inch ?quantity))
What this box does. A directive speech act. The KIF variable ?quantity is unbound — Alice is asking Bob to bind it. ask-one (not ask-all) because a single answer suffices. The label :reply-with opens a conversation thread.
2 · tell — Bob → Alice
(tell
  :sender       Bob
  :receiver     Alice
  :language     KIF
  :ontology     warehouse-stock
  :in-reply-to  query-tv-stock-01
  :content      (= (available-stock television-50inch) 137))
What this box does. An assertive speech act: Bob binds the variable and asserts the fact — 137 units on hand. :in-reply-to matches the thread label, so even in an asynchronous exchange Alice knows exactly which question this answers. On receipt, Alice updates her belief base.
3 · ask-one — Alice → Bob
(ask-one
  :sender      Alice
  :receiver    Bob
  :language    KIF
  :ontology    warehouse-stock
  :reply-with  query-tv-hdmi-02
  :content     (hdmi-slots television-50inch ?number))
What this box does. The same query pattern reused for a different function from the ontology, hdmi-slots, with a fresh thread label. The uniformity is deliberate: one protocol, any fact — Alice's code doesn't change per question.
4 · tell — Bob → Alice
(tell
  :sender       Bob
  :receiver     Alice
  :language     KIF
  :ontology     warehouse-stock
  :in-reply-to  query-tv-hdmi-02
  :content      (= (hdmi-slots television-50inch) 3))
What this box does. The final assertion: each television has 3 HDMI slots. Alice's goal is achieved — both facts are now in her belief base and she can proceed to a purchasing decision. Had Bob lacked the fact, he would reply with sorry instead.

Speech act terms and their function

KQML operationalises speech act theory (Austin 1962; Searle 1969): a message is an action, and the performative names which action. The terms used or implied in this dialogue:

TermSpeech act typeFunction in the dialogue
advertiseCommissive Bob commits to a capability — answering stock queries — enabling discovery.
ask-oneDirective Requests a single binding for the query's variable; the counterpart ask-all would request every matching fact.
tellAssertive Asserts a fact into the conversation; the receiver may adopt it as a belief.
sorryAssertive (negative) Graceful failure — the agent understood the request but cannot answer it.
:reply-with / :in-reply-to— Not performatives but conversation labels: they thread each answer to its question, permitting asynchronous exchange.
:ontology— Declares the shared vocabulary; the semantic ground both agents stand on.
Intent vs. content. The performative carries why the message was sent; the KIF content carries what it says. That separation is what makes the agents loosely coupled.

Extending the dialogue: brokered discovery

The core dialogue assumes Alice already knows Bob exists and that Bob can answer everything. The extended scenario below drops both assumptions. Four agents take part — Alice, Bob, a Facilitator (broker), and a Catalogue agent holding product specifications — and two ontologies are in play: retail-stock for inventory and product-spec for technical attributes.

Two ontologies. Stock lives in retail-stock; HDMI slots live in product-spec. That split is what makes Bob's sorry honest — and the broker necessary.

Breakdown, message by message

1–2 · register, advertise — Bob → Facilitator
(register  (bob :agent-type stock-controller))
(advertise (ask-one :content (stock ?item ?qty)))
Joining the society. Bob first registers his identity with the Facilitator, then advertises the class of queries he answers. Capability now lives in middleware, not in any requester's code.
3–5 · register, recommend-one, tell — Alice ↔ Facilitator
(register (alice :agent-type procurement))
(recommend-one :content (stock ?item ?qty))
  ⇢ (tell "bob, per his advertisement")
Discovery. Alice doesn't know Bob exists. recommend-one asks the Facilitator who can answer this?; the reply names Bob. The agents are matched by capability, never hard-wired.
6–7 · ask-one, tell — Alice ↔ Bob
(ask-one :content (stock (television 50-inch) ?qty))
  ⇢ (tell :content (= (stock (television 50-inch)) 37))
The familiar exchange. With Bob discovered, this is the core dialogue's opening query — a direct request and an assertion, threaded within the retail-stock ontology. 37 units on hand.
8–9 · ask-one, sorry — Alice ↔ Bob
(ask-one :content (hdmi-slots (television 50-inch) ?n))
  ⇢ (sorry "understood, but out of competence")
Honest failure. HDMI slots belong to the product-spec ontology, which Bob doesn't speak. He parsed the message and understood the intent — he simply isn't the agent to answer. sorry keeps the conversation alive instead of crashing it.
10–13 · broker-one → ask-one → tell → tell — via the Facilitator
(broker-one :content (hdmi-slots (television 50-inch) ?n))
  ⇢ Facilitator → Catalogue: (ask-one ...)
  ⇢ Catalogue → Facilitator: (tell (= (hdmi-slots ...) 4))
  ⇢ Facilitator → Alice:     (tell (= (hdmi-slots ...) 4))
Delegation. broker-one hands the whole problem to the Facilitator: find someone who knows, ask them, and return the answer. Alice never learns the Catalogue exists — the broker absorbs the routing. Each set has 4 HDMI slots.
14–15 · achieve, tell — Alice ↔ Bob
(achieve :content (reserved (television 50-inch) 20 alice))
  ⇢ (tell "reserved; (= (stock ...) 17)")
From knowing to doing. achieve asks Bob to make something true — reserve 20 units — rather than report what is true. The confirming tell shows the world changed: stock fell from 37 to 17. This is the step where Alice stops querying and starts procuring.

The extension adds four performatives to the core set — register and recommend-one for discovery, broker-one for delegation, and achieve for action — and shows the pattern that makes multi-agent systems scale: when one agent's competence ends, facilitation routes around the gap rather than forcing every agent to know every other. It also gives the ontology problem concrete form: Bob's sorry at message 9 is not an error but a boundary between two vocabularies, and the entire brokered detour of messages 10–13 exists to cross it.

Critical evaluation of the languages

KQML. KQML's lasting contribution is the idea that the communication layer should carry intent: performatives are speech acts, so agents interoperate by understanding why a message was sent without inspecting each other's internals. Its weaknesses are equally well documented. The specification never fixed a formal semantics — different implementations interpreted performatives inconsistently, and the performative set was open-ended, so two "KQML-compliant" agents could still fail to understand each other. It also has no notion of interaction protocols: nothing in the language guarantees that an ask-one will eventually receive a tell or sorry, so conversation structure is left to convention — as the ad-hoc :reply-with threading in this dialogue shows. FIPA-ACL addressed exactly these gaps by grounding its performatives in a formal semantics of beliefs and intentions and standardising interaction protocols, which is largely why KQML is now of historical rather than practical importance.

Why FIPA-ACL won. Formal semantics plus standard interaction protocols meant two independently built agents could finally rely on meaning the same thing by the same performative.

KIF. As a content language, KIF's strength is expressiveness: full first-order logic in a declarative, human-readable LISP syntax, able to state not just facts but rules, quantified statements, and meta-knowledge. That expressiveness is also its cost. Full first-order logic is undecidable in general, so nothing guarantees Bob can answer an arbitrary well-formed query; practical systems restrict themselves to a decidable fragment, at which point much of KIF's power goes unused. Its prefix s-expression syntax, natural in 1990s AI, is alien to modern tooling — today the same content would likely travel as JSON(-LD) or RDF, with OWL playing KIF's ontology role, precisely because those formats trade expressiveness for decidability, validation, and ecosystem support.

The pairing — and what neither language solves. The KQML/KIF split (intent in the envelope, knowledge in the content, semantics in the ontology) remains a genuinely good architecture; it is essentially the architecture of modern LLM tool use, where function-call messages are performatives and JSON schemas are miniature ontologies. But the pairing shares one unsolved dependency: both languages assume the ontology problem away. Neither provides any mechanism for two agents to discover, negotiate, or verify that they mean the same thing by available-stock. In this dialogue the shared vocabulary is simply asserted; in open systems, that assumption is where interoperability actually breaks. The languages guarantee syntactic and pragmatic agreement — semantic agreement must come from elsewhere.

See it break. In the interactive playground below, sending a function outside the ontology, or free-form natural language as KIF content, produces exactly the failures this evaluation predicts — Bob replies sorry every time.
